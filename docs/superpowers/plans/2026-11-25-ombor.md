# Омбор бошқаруви Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A phone-first warehouse web system (requests, payment approval, receipts) with logins, deployable free on Cloudflare.

**Architecture:** One Cloudflare Worker (`apps/ombor`) serves a JSON API (Hono) under `/api` and the built React app as static assets. Data lives in D1 (SQLite). Excel import/export run in the browser.

**Tech Stack:** TypeScript, Hono, Cloudflare Workers + D1, React 19, Vite, read-excel-file, write-excel-file, Vitest (API tests against a local D1 via `wrangler` `getPlatformProxy`).

**Spec:** `docs/superpowers/specs/2026-11-25-ombor-design.md`

## Global Constraints
- OvozYoz (`apps/web`, `apps/desktop`, `packages/core`) is not modified.
- No workbook data in the repository.
- Roles: `admin`, `warehouse`, `supply`, `boss`. Request statuses: `open`, `approved`, `received`. Payment statuses: `pending`, `approved`, `rejected`, `paid`.
- Money and quantities are REAL; dates are `YYYY-MM-DD` strings.
- UI text only through the `uz`/`ru` dictionaries.

## Review Focus
- A user without the role calls a write endpoint directly → 403, nothing written.
- Receiving more than was requested → allowed, «Қолди» shows 0, never negative.
- Importing the same workbook twice → second import adds nothing.
- Two requests created in the same month → different numbers.
- A disabled user's existing session → rejected on the next call.
